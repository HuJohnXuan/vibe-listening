# 测试说明

## 当前覆盖范围

- 氛围生成在无记忆时提供歌曲背景，在有记忆时将该记忆加入专属氛围说明；
- 页面展示 Vibe Listening 品牌和“给这首歌留一句记忆”入口；

- 页面打开后渲染左侧黑胶区、右侧歌曲与发现区、底部控制区；
- 页面使用设计说明中确认的主色与强调色令牌；
- 页面不出现搜索、登录等范围外入口；
- 构建产物能够由站点运行时正常渲染；
- 首页显示默认歌曲、歌手、歌词片段和 Listening Notes；
- 首页固定渲染 3 条带推荐理由的 Tonight’s Picks；
- 每条 Tonight’s Picks 都提供播放和加入 Later 两个独立操作；
- 点击推荐歌曲会复用音频控制器切换并播放，加入 Later 后按钮显示已加入；
- Radar 提供展开和收起入口，并始终渲染四条命名发现路线；
- Radar 展开时每条路线显示对应歌曲和自然语言理由，切歌后同步刷新；
- Radar 使用暖棕唱片内页面板和短距离淡入，不包含扫描圆环或网格效果；
- Picks 与 Radar 的歌曲均可加入 Later，重复加入会被忽略；
- Later 面板按加入顺序展示歌曲，并支持队列内播放和单项移除；
- 喜欢按钮具备可读标签、`aria-pressed` 状态和玫红选中反馈；
- 播放、展开和列表操作具备统一的悬停、按下与键盘聚焦状态；
- 进度条拖动点默认隐藏，并在悬停或聚焦时显示；
- 页面包含可操作的本地音频、播放控制和进度拖动输入；
- 上一首和下一首索引在曲库首尾正确循环；
- 播放时间按 `m:ss` 格式输出，无效时间回退到 `0:00`；
- 页面以正在播放的音频歌曲作为唯一当前歌曲状态源；
- 浏览器切歌时检查封面、歌曲信息、歌词、Notes 和 3 条 Picks 同步更新；
- Listening Notes 渲染一句听感说明、四个标签分组和八个紧凑标签；
- Notes 标签使用奶油色或香槟金浅底、深棕文字，标题权重低于 Picks；
- 曲库包含 8–12 首 ID 唯一的完整曲目；
- 每首曲目的封面和试听资源均为有效本地文件；
- 10 首歌曲均使用已确认的标题匹配纯图案封面，目录映射逐首校验；
- 人工推荐关系引用有效曲目、排除自身并包含自然语言理由；
- 每首曲目均准备 Same Artist、Same Room、Similar Voice 和
  Production Texture 四条发现路线。
- 每首曲目固定得到 3 首带理由的 Tonight’s Picks；
- 人工关系排在标签重合度回退结果之前；
- 当前歌曲、无效目标和重复目标不会进入推荐结果；
- Later 状态保持加入顺序、忽略重复曲目 ID，并可仅移除指定项；
- Later 按队列顺序解析完整曲目，并忽略曲库中不存在的 ID；
- 样式中不包含青色、蓝色或紫色科技辉光；
- 常见笔记本宽度收紧画布边距，歌名使用单行省略，歌词片段最多显示两行；
- 曲目结束后只停止当前试听，不强制自动接管下一首；
- 最终文档包含未来 API 接入边界和逐项验收记录；
- 人工关系不足、只有当前歌曲、当前歌曲不存在等边界有明确行为；
- Radar 数据与展开页面始终包含四个稳定分组；
- 浏览器手动验收播放、暂停、切歌、拖动进度及唱片/唱臂动效。
- 唱臂活动组件播放时围绕固定转轴移动，转轴底座不参与变换。
- 白色唱头嵌套在唱臂杆末端，不作为独立悬浮元素定位。

## 运行方式

```bash
npm test
```

测试命令先执行 Next.js 生产构建，再运行 Node.js 内置测试。渲染断言读取本次构建的 `.next/server/app/index.html`；不再读取 Vite 的 `dist`。这些是产物和业务逻辑检查，不代替浏览器交互验收。

3D 房间、每曲记忆、重播和尺寸回归步骤见 [3D_ROOM.md](3D_ROOM.md)。

浏览器最终验收尺寸为 `1440 × 900`、`1366 × 768` 和 `1024 × 768`。检查每个尺寸
下无水平溢出、左右主区无重叠、底部控制区不遮挡内容，并连续操作播放、切歌、Radar
和 Later。
