# 3D 听歌房间

## 本次方向

解决“房间太 2D”：用真实的透视相机、几何体、材质、光源和阴影搭建可转动的听歌房间。保留原黑胶唱机特写作为可切换视图和 WebGL 不可用时的回退。

房间包含木地板、护墙板、沙发与靠垫、地毯、茶几、壁炉、落地灯、窗帘、唱片柜、音箱、绿植与唱机。唱片和唱臂消费播放器状态；封面来自已有本地曲库。

## 氛围与隐私

### 房间内互动

- 点击 3D 唱机：复用播放器的播放/暂停操作，底部按钮与唱片动效保持同步。
- 点击落地灯：切换实际灯光和灯罩发光；点击壁炉：切换火焰与火光。
- 点击窗户：晴 → 雨 → 雪 → 晴；手动天气保持到点击“跟随歌曲”，不修改歌曲记忆。
- 顶部提供相同操作的键盘可达按钮，开关通过 `aria-pressed` 表达状态；悬停物件会显示提示。
- 射线检测使用宽松物件范围；指针移动超过 6 CSS 像素视为拖动，取消此次点击，多指操作不触发物件。
- 灯光、炉火与手动天气仅保存在当前页面；刷新恢复默认。

- 歌曲情绪标签选择壁炉、落日或深夜基调。
- 记忆包含雨、雪/冬、夕阳/黄昏、深夜等关键词时，调整场景灯光与窗外天气。这是本地规则匹配，不是对任意文本的 AI 理解。
- 记忆按歌曲 ID 保存在当前页面内存中，切歌互不串用，切回恢复；刷新清空，不上传、不写入浏览器存储。
- 降低动态效果偏好下，停止唱片、炉火与天气动画；手动选择视角和场景仍生效。
- 渲染上限 30 FPS、像素比上限 1.5；使用静态阴影贴图；页面隐藏、场景不可见或进入唱机特写时跳过渲染。
- 组件卸载释放材质、几何、纹理、事件和渲染器；WebGL 初始化失败或上下文丢失时使用原唱机视图。

## 同时修复

- 右侧允许独立滚动；推荐行保留最低高度；Radar/Later 在文档流中展开，避免重叠。
- Later 中点击当前暂停歌曲会继续播放；当前歌曲结束后可从头重播。

## 验收方式

```bash
npm test
npm run lint
npm run dev
```

浏览器回归流程：

1. 打开首页，等待房间出现；拖动视角，或用“从左侧看房间 / 重置房间视角 / 从右侧看房间”按钮操作。
2. 为第一首歌填写“下雨的末班车”，确认雨夜场景；切到下一首，记忆应为空；切回第一首，恢复原记忆与雨夜场景。
3. 输入“冬日炉边”，确认雪景；清空输入，回到歌曲默认场景。
4. 从 Picks 加入歌曲到 Later，展开 Later 播放；试听结束后再次点击该曲，应从 0 秒重播；暂停后再次点击，应恢复播放。
5. 操作音量、进度、上一首、下一首、喜欢和移除队列歌曲。
6. 在 1440×900、1366×768、1024×768 下滚动右侧，确认三条推荐无重叠，展开面板可访问，底部控制保持可见。
7. 切到“唱机特写”后返回“房间全景”，确认两种视图和音频状态连续。
8. 直接点击房间里的灯、壁炉、窗户与唱机，确认模型效果和按钮状态一致。从物件上开始拖动视角，开关不应误触。使用 Tab/Enter 操作顶部按钮应产生相同结果。

仍是 PC 浏览器 MVP；未加入真实音乐服务、本地文件导入或移动端重设计。当前 10 首曲目仍为 6 秒合成试听。生产构建与本地预览验证不代表线上部署完成。
