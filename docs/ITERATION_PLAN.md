## 1. 产品方向与使用边界

**产品主线：把自己的音乐带进来，拥有一个可以再次回来的听歌空间。**

面向使用电脑浏览器、愿意导入自己音乐的用户，支持工作、阅读、放空等连续听歌场景。音乐播放是基础；房间、声音氛围和住客形成辨识度。

### 持续遵守的约束

- **已确认**：每个用户可导入自己的音乐，音乐保存在各自设备的浏览器本地；目前不需要云端音乐存储或后台数据库。
- **已确认**：空间同时包含现实生活房间与幻想空间，小人会活动，并随房间变化穿搭。
- **已确认**：小人避免过度幼态，保留眼睛，不增加鼻子和嘴巴；已接受短发、耳机和简洁造型方向。
- **已确认**：重要视觉变化先给预览。本文件记录的视觉建议不等于新效果图已获得确认。
- **已有**：歌曲私人记忆只存在当前页面内存中，刷新清空。后续保存队列或场景时，不顺带持久保存这段文字。
- **建议默认**：先完善桌面浏览器体验；不把手机重设计、原生 App 或账号系统作为本轮前置条件。

## 3. 分阶段范围

| 阶段 | 目标 | 规划纳入 | 交付物 |
| --- | --- | --- | --- |
| A：连续听歌 | 用户选好音乐后能持续听，下次还能继续选择 | 队列/续播、搜索/收藏、简单歌单、基础状态恢复 | 可运行版本、验收记录、相关文档更新 |
| B：自己的房间 | 一键回到熟悉的空间与声音 | 场景保存、少量环境声、小人衔接优化、统一房间光线 | 先出视觉/交互预览，再实现与验收 |
| C：按使用反馈深化 | 增加实际需要的沉浸与便利能力 | 从音频联动、本地歌词、PWA/离线、系统控制中择需推进 | 单项需求与试用验证，不整包默认实施 |

阶段 A、B 为主要迭代清单，C 为后续候选集合。顺序不代表工期承诺；尚无开发排期和投入估算。每阶段结束记录已实现内容、偏差与用户反馈，再决定后续范围。

## 4. 阶段 A：功能与行为

### A1. 统一播放队列与自动续播

**规划纳入**：自动下一首、查看队列、下一首播放、加入队尾、移除、重排、顺序/随机/单曲循环/列表循环。

**建议默认规则**：

- 曲库是全部音乐，歌单是用户整理的集合，队列是实际播放顺序；三者职责分开。
- Later 保留“稍后想听”的用途，提供加入队列入口，不再让用户误以为列表会自动续播。
- 从自己的歌单或曲库开始播放时，不把演示音频自动混入队列；演示体验使用独立队列。
- 顺序播放到末尾停止，列表循环回到首曲，单曲循环重播当前曲。
- 随机模式维护明确的本次顺序；上一首、下一首与刷新恢复使用同一顺序，不每次重新抽签。
- 播放中的曲目移出待播队列不立即打断音频；从曲库删除当前曲的应用副本时，停止并明确提示，不播放错误对象。
- 首期同一曲目在队列中保留一次；再次加入时定位并提示。重复排同曲作为后续可调整项。
- 清空队列、曲目不可用、播放失败均有明确状态；失败不形成无限重试或快速跳歌循环。

### A2. 搜索、收藏、筛选与简单歌单

**规划纳入**：歌名/歌手搜索、最近加入排序、情绪/房间筛选、持久收藏、自建歌单。

**建议默认规则**：

- 查询忽略首尾空格与英文大小写，空查询展示全部；无匹配时保留筛选条件并提供清除入口。
- 歌单提供新建、改名、删除、增删曲目与排序；删除歌单或取消收藏不删除音频副本。
- 歌单按稳定歌曲 ID 关联；沿用当前文件内容哈希，不以临时 Blob URL 或文件路径作为身份。
- 标签缺失时允许手动整理，不生成没有来源的情绪、曲风和相似曲目。
- 首期保持轻量界面，不建立复杂艺术家百科、评分体系或多级目录编辑器。

### A3. 本地恢复与基础数据保护

**规划纳入**：本地保存收藏、歌单、队列、随机顺序、当前曲目、进度和音量；保存结构带版本。

**建议默认规则**：

- 重开页面恢复到暂停状态，由用户点击播放，不因恢复而突然发声。
- 先等本地曲库读取完成，再恢复歌曲关系；已移除的歌曲显示缺失或被安全过滤。
- 进度按适当间隔及暂停/切歌等节点保存，避免每次绘制都写入存储。
- 歌曲私人记忆继续临时保存；历史播放记录若加入，先明示本地用途并提供清除入口。
- 写入失败保留当前可用状态并提示；不能显示“保存成功”却未完成持久化。
- 保持现有网站地址，避免仅因换域名让用户误以为曲库丢失；跨地址迁移需另做方案。

**候选增强**：元数据与歌单导出/导入。仅导出这些资料时明确不包含音频；完整音频备份包不属于阶段 A 的基础范围。

## 5. 阶段 B：功能与行为

### B1. 保存“我的听歌场景”

**规划纳入**：将房间、光线、天气、关联歌单、环境声组合和住客偏好保存为可命名场景，支持恢复、更新与删除。

**建议默认字段**：`id`、`name`、`roomType`、`daylight`、`weather`、`playlistId`、`ambientMix`、`residentPreferences`、`schemaVersion`。这是设计草案，落地时与现有数据契约统一。

**建议默认规则**：

- 初版示例：“雨夜看书”“天台晚风”“云端放空”，均为可修改的预设，不自动收集用户文字。
- 恢复场景先改变空间与偏好；不自动打断当前歌曲。切换关联歌单由用户单独触发。
- 场景不保存角色走到一半的坐标、瞬时姿势等脆弱状态，只保存显示与偏好。
- 关联歌单已删除时恢复空间，提示歌单不可用，不让整个场景恢复失败。
- 不保存私人记忆、原始文件路径或音频本体到场景配置。
- URL 分享为候选；初版先保证本地保存可靠。

### B2. 少量环境声与独立音量

**规划纳入**：客厅雨声/炉火、天台轻风、云端柔和风声等少量素材；音乐和环境声独立控制。

**建议默认规则**：

- 首次默认关闭，由用户主动开启；不把视觉下雨自动等同于允许播放雨声。
- 允许选择画面与环境声联动，选择后随场景保存；保留独立开关。
- 暂停音乐不强制关闭已主动开启的环境声；“全部暂停”明确停止所有声音。
- 切场时平滑淡出/淡入，避免多段环境声意外叠加；失败只影响环境声，不打断歌曲。
- 素材需有可追溯的来源与使用许可；检查循环接缝、噪点、音量和是否喧宾夺主。

### B3. 住客动作与情境优化

**规划纳入**：先完善转身、移动、坐下、起身、挥手与回到原状态的衔接，之后增加少量环境关联行为。

**建议默认规则**：

- 用户指令优先；移动中可改目标，不能因自动活动抢走控制。
- 挥手优先在当前安全位置完成，之后回到此前合理的停留/活动状态。
- 下雨时偶尔看窗、音乐暂停后回归安静；切歌只做短暂且低频的反馈。
- 同一动作不高频重复；不强制用户照顾、喂养、签到或完成任务。
- 路径避开家具，坐姿贴合家具，近景不裁切头部与耳机；不能长期挡住核心操作。
- 保留自由活动、固定停留与隐藏；尊重减少动态效果偏好。

### B4. 房间整体一致性

**规划纳入**：处理现有光线、远景和三种空间的视觉一致性；不默认再建一批房间。

- 城市天台：远景增加高低、间距、轮廓与远近层次，避免重复等宽方块；昼夜选择与天空、楼体明暗一致。
- 温暖客厅：保持沙发、唱机与炉火的生活关系，控制木材、灯光和暖色饱和度。
- 云端小屋：保留幻想感，以云层、拱架、轻材质与空间留白表达；控制粒子数量与闪动。
- 天气、灯光和音效状态在控制面板与画面中一致，可手动覆盖并恢复跟随歌曲。

## 6. 视觉与交互风格基线

### 6.1 总体方向

**建议方向：成熟、安静的微缩模型场景，带有黑胶听歌的温度。**

使用柔和几何、可信的家具比例、克制的材质和局部暖光。房间带模型玩具的亲近感，角色保持简洁，但不继续放大头部、缩短四肢或增加婴儿化表情。

页面以房间为主视觉，曲库、队列、设置按需展开；底部播放控制保持可达。第一期优化现有结构，重要布局变化先出可点击预览。

### 6.2 颜色、材质与字体

以下为建议设计起点，不要求每个场景完全同色，也不表示已经选定新设计稿。

| 层次 | 参考色/表现 | 使用规则 |
| --- | --- | --- |
| 应用背景 | 深棕 `#201010`、暖棕 `#402020` | 复用现有色彩变量，保证文本清晰，控制背景纹理 |
| 面板 | 暖灰棕 `#49352e` | 少量边框与层次，不叠加大量玻璃效果 |
| 文字与强调 | 米白 `#f0f0e0`、香槟金 `#f4d28a` | 金色用于选中/焦点等关键状态，不铺满所有控件 |
| 客厅 | 胡桃木、燕麦、苔绿、暖琥珀 | 暖光有明暗层次，避免整体一片橙黄 |
| 天台 | 蓝灰、暮紫、米白、少量暖灯 | 城市轮廓疏密变化；冷暖与时间相符 |
| 云端 | 米白、灰蓝、浅木色、低饱和天空 | 留白、云层深度与柔和光，不靠大量发光堆幻想感 |
| 音乐状态 | 延续现有进度/喜欢强调色 | 只标记有效状态，不让动效持续争夺注意力 |

中文正文优先沿用已有系统字体回退链；装饰手写字体只用于品牌标题。按钮文案、次要说明和空状态保持易读，不能为“精致”把字号压得过小。

材质以哑光布料、木材、纸、柔和金属为主；减少塑料高光、无必要的强反射和重复贴图。

### 6.3 小人的造型与穿搭

- **已确认方向**：短棕发、棕色耳机、仅眼睛的面部；保持上一轮已接受的年龄感。
- **已有穿搭**：客厅苔绿上衣与棕裤；天台蓝灰外套与深裤；云端米白上衣与灰蓝裤。
- **建议优化**：通过衣物轮廓、领口/袖口、鞋型与少量材质差异体现换装，保持角色身份一致。
- **建议动作气质**：重心平稳、小幅点头、缓慢看窗、自然停留；避免持续蹦跳、夸张挥舞和高频表情反馈。
- **候选**：少量可选穿搭与固定配饰，先验证与三种房间的协调，再考虑更多角色。

### 6.4 动效与音画关系

- 基础操作反馈清楚，切换有柔和过渡，不用大幅视角飞行和连续镜头切换。
- 音频联动若进入阶段 C，只作用于少量局部元素；提供关闭和降低动态的选项。
- 标签决定房间语义，实时音量只控制动态强弱；不把音量变化宣传为情绪识别或精确节拍分析。
- 遮挡、眩晕、持续 GPU 负载和音量叠加都属于验收事项。

## 8. 工具与技术选择清单

原则：复用当前实现、浏览器原生能力和已装依赖；以下按用途选择，不要求全部安装，也不把“可能需要”写成已经使用。

| 工作 | 优先方案 | 何时才增加工具/依赖 | 状态 |
| --- | --- | --- | --- |
| 页面与交互 | Next.js、React、TypeScript、现有 CSS/样式变量 | 现有控件无法满足实际行为时再评估组件依赖 | 项目已有 |
| 三维房间与住客 | Three.js、现有场景/角色/路径模块 | 只有程序化造型成为明确瓶颈时再评估模型资源 | 项目已有 |
| 音乐资料解析 | `music-metadata` | 增加歌词或新字段时先核验其已有能力 | 项目已有 |
| 曲库与状态保存 | IndexedDB；少量偏好可用浏览器存储 | 数据复杂度实际增加后，再评估 Dexie 等封装；当前不默认新增 | 浏览器原生 |
| 播放与混音 | HTMLAudioElement；环境声按需用 Web Audio | 多轨路由、淡化和实际兼容问题出现后再判断是否需音频库 | 原生优先 |
| 音频视觉联动 | Web Audio `AnalyserNode` | 只有明确需要独立可视化模式时评估 Butterchurn/WebGL 2 | 阶段 C 候选 |
| 系统媒体控制 | Media Session API，能力检测与回退 | 原生系统集成超出浏览器能力时才讨论桌面封装 | 阶段 C 候选 |
| 歌单/场景导出 | JSON、Blob、原生下载与文件选择 | 要做完整音频包且确有需求，再评估压缩工具 | 后续候选 |
| 视觉构思与预览 | HTML/CSS 可点击原型；图像生成工具制作概念图 | 新材质/角色方向需要比较时再出图；概念图不当作实机截图 | 按需使用 |
| 精细模型与动作 | 先改现有几何与动作 | 需要骨骼/精细服装时再考虑 Blender、glTF；不要求用户先安装 | 可选，未核验安装 |
| 设计协作 | Markdown、截图与可点击页面 | 需要多人设计交接再用 Figma，非必需 | 可选，未接入 |
| 环境声素材处理 | 明确许可的素材；按需用 Audacity/FFmpeg 检查剪辑与循环 | 素材需要去噪、统一响度或转换格式时使用 | 可选，未核验安装 |
| 浏览器验收 | 可用浏览器自动化、Playwright、实际浏览器人工检查 | 复用可用环境，避免反复安装独立浏览器；失败时采用等效路径 | 每次运行时核验 |
| 回归验证 | 现有 Node 测试、ESLint、Next.js 生产构建 | 为状态流转、存储和必要边界补测试，不新增只复述实现的测试 | 项目已有 |
| 发布 | GitHub、现有 Vercel 项目 | 功能验收后按当次授权提交与发布 | 已有发布路径，执行前查实 |
| 离线安装 | Manifest、Service Worker、缓存策略 | 先明确 Next.js 版本兼容与更新策略，再选 PWA 工具 | 阶段 C 候选 |

本轮不需要接入音乐平台插件、搜索下载服务、账号、云数据库或大模型 API。未来若范围变化，记录新增依赖的用途、数据流、成本、许可与替代方案。

## 9. 验收清单

以下验收项已于 2026-10-17 完成，逐项证据见 [V0.2 验收记录](ITERATION_ACCEPTANCE_2026-10-17.md)。

### 阶段 A

- [x] A-01：给定三首本地歌曲组成的顺序队列，当前曲结束后播放下一首，界面、进度与实际声音一致。
- [x] A-02：从用户歌单播放时，自动续播不插入演示曲；手动演示入口仍可用。
- [x] A-03：加入下一首、队尾、重排、移除后，队列展示与实际顺序一致。
- [x] A-04：随机播放前后切换及刷新恢复后，能按保存顺序定位；顺序/单曲循环/列表循环末尾规则符合说明。
- [x] A-05：刷新后恢复歌曲、队列、进度、音量和收藏，保持暂停；缺失曲目不会恢复到错误歌曲。
- [x] A-06：搜索、筛选、空结果、清除条件、最近加入排序可用；输入时不误触播放快捷键。
- [x] A-07：歌单增删改和顺序保存正确；删歌单与取消收藏不删除音频。
- [x] A-08：存储不可用、超额、写入失败与音频失败有可理解提示，不误报成功或无限重试。
- [x] A-09：私人记忆刷新清空，未进入新持久化数据；房间切换不重启歌曲。

### 阶段 B

- [x] B-01：同一场景保存后重开可恢复空间、声音与偏好；歌单缺失只影响关联歌单。
- [x] B-02：恢复场景不突然播放新音乐，不将私人记忆、路径或音频放入场景数据。
- [x] B-03：首次无环境声；开启后可独立调音量、关闭或全部暂停；循环无明显接缝，切场不意外叠加。
- [x] B-04：三种房间及三套穿搭可辨识，近看住客时头部、耳机与身体不被错误裁切。
- [x] B-05：转身、行走、坐下、起身、挥手衔接合理，途中改目标有效，自动活动不抢指令。
- [x] B-06：天台远景的层次和昼夜表现与光线选项一致，客厅与云端的材质风格协调。
- [x] B-07：减少动态效果、隐藏住客、后台绘制节流与 WebGL 回退保持有效。
- [x] B-08：可用键盘操作关键控件，拖动视角不误触物件；开关与焦点状态清楚。

性能记录需注明设备、浏览器、分辨率、活动场景和测试步骤；先采集现状，再确定具体预算，不提前编造帧率或内存提升值。

## 10. 阶段 C 候选与暂缓项

| 方向 | 最小起点 | 进入条件 |
| --- | --- | --- |
| 实时音频联动 | 少量局部元素随能量轻微变化 | 先验证性能、减少动态效果与实际感受 |
| 本地歌词 | `.lrc`/文本导入、绑定、偏移 | 试用者确有歌词需求，准备端到端显示验收 |
| 系统控制/快捷键/睡眠定时 | 一组常用控制与计时停止 | 按真实使用情境选择，先明确浏览器兼容 |
| PWA 与离线 | 安装入口、外壳缓存、断网冷启动 | 明确升级策略，并验证本地音频恢复 |
| 元数据/歌单备份 | 小型 JSON 导入导出 | 本地组织数据有积累，明确不包含音频的提示 |
| 更多房间/穿搭/装饰 | 有限模板与装饰槽位 | 从已被重复使用的场景出发，再投入美术 |
| 场景分享 | 仅空间与混音参数 | 明确分享范围，排除私人内容与本地文件 |

暂缓：在线音源聚合/下载、云音乐存储、账号与多端同步、开放插件商店、AI 情绪识别与住客对话、完整家具沙箱/养成系统、原生多端重写、专业无缝与复杂交叉淡化。这些方向不因竞品拥有而自动进入计划。
