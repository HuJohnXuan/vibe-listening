# 房间共鸣与关联唱片设计规格

日期：2026-07-30  
状态：阶段 2 待用户整体确认  
范围：只定义设计、数据契约、模块边界和实施影响，不包含实施计划或代码修改。

## 1. 已确认决策

- 页面采用“房间物件”布局：关联唱片在唱盘旁出现，不进入常规推荐列表。
- 关联唱片采用两步交互：第一次点击翻面，第二次点击切换并播放。
- 房间共鸣是每首歌的人工固定状态，只在切歌后用 3–6 秒柔和过渡切换。
- 共鸣不跟随鼓点或播放进度持续变化，不引入频谱、粒子和扫描动画。
- 认真聆听允许一次进度拖动；第二次拖动取消当前播放周期的关联唱片资格。
- 主动切歌会结束当前周期，并为新歌曲建立新的播放周期。
- 不增加拒绝按钮，也不把未点击推断为拒绝。
- 第一版只在当前会话中排除刚听过和刚跳过的歌曲，不建立长期用户画像。
- 采用独立核心状态架构，不把业务判断继续堆入播放器页面 Hook，也不引入全局状态库。

## 2. 页面信息层级

### 2.1 第一层：音乐播放

- 左侧房间区域保留唱盘、当前唱片、唱臂和播放状态。
- 右侧顶部保留当前歌曲、歌手、专辑、歌词片段与基础播放控制。
- 当前歌曲和播放控制始终是最高操作优先级，文字和控制条不参与房间情绪变色。

### 2.2 第二层：房间回应

- 房间结构、家具位置和主要材质保持稳定。
- 共鸣只改变灯光、壁炉、窗影、材质质感、前后景亮度与空间纵深。
- 不常驻展示参数值、评分或“算法状态”面板。
- 聆听笔记保持低视觉权重，用自然语言帮助理解歌曲，不解释内部参数。

### 2.3 第三层：音乐发现

- 移除首屏常驻的 `Tonight’s Picks`。
- 关联唱片作为唱盘旁的房间物件，负责一次克制的偶遇。
- 音乐雷达保留，负责用户主动展开后的多路线探索。
- 稍后播放保留，负责用户明确保存的歌曲。
- 关联唱片、音乐雷达和稍后播放不重复堆叠同一组推荐内容。

### 2.4 中文界面

- 功能名称、按钮、状态、工具提示、错误提示和无障碍文本使用中文。
- 歌曲、歌手和专辑的官方名称保持原文，不自行创造中文译名。
- `Tonight’s Picks` 从界面和验收文案中移除；`Radar` 和 `Later` 分别显示为“音乐雷达”和“稍后播放”。

## 3. 房间共鸣数据契约

每首曲目必须提供一份人工配置的 `RoomResonanceProfile`：

```ts
type ResonanceLevel = 0 | 1 | 2 | 3 | 4;

type DominantResponse =
  | "lighting"
  | "fire"
  | "material"
  | "depth";

interface RoomResonanceProfile {
  emotionTemperature: ResonanceLevel;
  rhythmEnergy: ResonanceLevel;
  productionTexture: ResonanceLevel;
  soundDistance: ResonanceLevel;
  dominantResponse: DominantResponse;
  relatedCueRatio: number;
}
```

字段语义：

- `emotionTemperature`：从温暖亲密到冷静疏离；最低档仍保留暖棕基底。
- `rhythmEnergy`：从缓慢平稳到轻微推动；不映射为鼓点闪烁。
- `productionTexture`：从模拟粗粝到清晰洁净。
- `soundDistance`：从贴耳私密到开阔悠远。
- `dominantResponse`：指定每首歌最明显的一类房间回应，避免四个维度同时抢夺注意力。
- `relatedCueRatio`：人工标注的音乐节点，使用曲目总时长的比例表示；必须晚于认真聆听阈值。

适配器在数据进入业务层前验证：

- 四个共鸣值必须是 `0–4` 的整数；
- `dominantResponse` 必须是已定义枚举；
- `relatedCueRatio` 必须在 `(1/3, 1)` 范围内；
- 缺少或无效配置时不伪造参数，曲目数据验证失败并返回友好错误。

## 4. 认真聆听判定

每次切入一首歌曲时创建独立播放周期。周期只保存在内存中，刷新页面后重置。

关联唱片出现必须同时满足：

1. 连续有效聆听时间达到曲目时长的三分之一；
2. 当前周期的进度拖动次数不超过一次；
3. 播放位置到达该曲目的 `relatedCueRatio`；
4. 推荐服务找到可信且未被本次会话排除的关联曲目。

行为边界：

- 有效聆听时间只累计音频实际处于播放状态的时间；暂停期间不累计，向前拖动跨过的区间也不计入。
- 暂停不会清空已累计的有效聆听时间。
- 第一次拖动被记录但不取消资格。
- 第二次拖动立即将当前周期标记为不合格，之后不恢复。
- 上一首、下一首、音乐雷达切歌、稍后播放切歌和关联唱片切歌都会结束旧周期。
- 新歌曲从零开始新周期；不继承旧歌曲的时间、拖动次数或关联唱片状态。
- 当前会话维护最近 3 条播放结果的队列，每条记录曲目和“已听过”或“已跳过”；达到三分之一后离开记为“已听过”，此前离开记为“已跳过”。
- 未点击关联唱片不算拒绝。
- 不计算投入度分数，不通过停留、悬停或未操作推断用户偏好。

## 5. 关联唱片状态机

状态：

1. `hidden`：默认状态，不渲染空卡槽、倒计时或解锁提示。
2. `front`：条件满足后短距离滑入、轻微转动并渐显；只展示封面。
3. `dimmed`：出现后 8 秒内没有悬停、聚焦或点击，唱片用约 4 秒逐渐降低亮度和边缘对比，但不消失。
4. `back`：第一次点击后翻面，不中断当前播放；展示歌曲、歌手、音乐血缘说明和“加入稍后播放”。
5. `consumed`：第二次点击后切换并播放关联歌曲，旧播放周期结束。

交互规则：

- 悬停或键盘聚焦使 `dimmed` 恢复清晰，但不改变业务状态。
- 每个播放周期最多选择并展示一张关联唱片。
- 候选在周期创建时选定并冻结，当前周期内不自行换成另一张。
- 背面的“加入稍后播放”只保存歌曲，不切歌、不结束当前播放周期。
- 没有可信关系或候选均被排除时，状态始终保持 `hidden`。
- 第二次点击使用现有切歌语义：切换后自动开始播放。
- 减少动态模式下取消滑入、转动和三维翻面，改用即时状态切换或短淡化；功能和焦点顺序保持一致。

## 6. 推荐选择规则

关联唱片沿用现有“人工策展优先、标签关系补充”的原则，但输出从三首列表收敛为一首候选：

1. 排除当前歌曲；
2. 排除当前会话中最近听过和刚跳过的歌曲；
3. 优先选择人工策展关系；
4. 人工关系不可用时才使用标签重合补充；
5. 没有可信候选时返回空结果。

音乐血缘说明只解释“为什么值得接着听”，不显示匹配度、热度、算法或营销式措辞。

第一版没有拒绝入口，因此不维护 `rejectedTrackIds`，也不以任何隐式行为代替明确拒绝。

## 7. 模块边界

采用单向依赖：`UI → services → core`，本地目录通过适配器向服务层提供数据。

### 7.1 核心层

- 房间共鸣模块：把 `RoomResonanceProfile` 转换为与 UI 无关的房间状态。
- 认真聆听模块：接收播放时间、曲目时长、拖动和切歌事件，输出资格状态。
- 关联唱片模块：管理 `hidden → front/dimmed → back → consumed` 状态迁移。
- 推荐排序模块：过滤会话排除项，并选出一个冻结候选。

核心层不依赖 React、浏览器音频对象、CSS 或第三方库。

### 7.2 服务层

- 组合当前曲目、房间共鸣、播放周期和关联候选。
- 负责把适配器错误转换为业务错误。
- 音乐雷达继续使用现有发现路线，不由关联唱片状态机管理。

### 7.3 适配器层

- 曲目目录增加共鸣参数和音乐节点。
- 推荐目录继续保存人工策展关系和自然语言关系说明。
- 真实音乐文件、许可证证据和原创封面在后续实施子任务中接入，本阶段不下载资源。

### 7.4 UI 层

- 当前过大的 `player-page.tsx` 只做与本功能直接相关的职责拆分。
- 房间舞台、当前歌曲信息、关联唱片、音乐雷达和稍后播放成为边界明确的组件。
- 播放 Hook 提供时间、时长、拖动和切歌事件，不承载推荐排序或状态机规则。
- UI 根据业务状态渲染，不自行推断资格或重新选择候选。

## 8. 错误与降级

- 曲目共鸣配置无效：阻止无效数据进入核心层，向界面返回简洁中文错误，不暴露字段堆栈。
- 关联候选为空：保持 `hidden`，不显示错误、占位或解锁失败提示。
- 推荐关系指向不存在的曲目：记录结构化业务错误并跳过该关系。
- 音频播放失败：沿用播放器现有错误展示；关联唱片不得显示为已成功切换。
- 减少动态设置可用时：不删除功能，只替换非必要空间动画。

## 9. 测试范围

### 9.1 单元测试

- 四类共鸣参数的正常值、最小值、最大值和非法值。
- 三分之一阈值前后、音乐节点前后和暂停恢复。
- 一次拖动仍合格，第二次拖动取消资格。
- 切歌后周期完全重置。
- 每周期只冻结一个候选，没有可信关系时返回空结果。
- `hidden/front/dimmed/back/consumed` 的合法迁移和非法迁移。
- 第一次点击不切歌，第二次点击才切歌。
- 人工策展优先、标签补充，以及最近听过和刚跳过排除。

### 9.2 集成与界面测试

- 播放事件能驱动认真聆听状态，但 UI 不直接实现规则。
- 关联唱片出现、渐暗、聚焦恢复、翻面、加入稍后播放和第二次点击切歌。
- `Tonight’s Picks` 不再渲染；音乐雷达和稍后播放仍可用。
- 切歌后房间状态在约 3–6 秒内平稳过渡，核心文字和控制条保持可读。
- 中文功能名称、操作提示和无障碍文本一致。
- 减少动态模式下无三维翻面或滑入，但完整键盘流程仍可完成。

## 10. 实施前变更影响分析

本功能预计影响超过 3 个文件，实施前必须按子任务拆分，不混合完成。

| 影响区域 | 当前状态 | 必要变化 | 主要风险 |
| --- | --- | --- | --- |
| 曲目类型与目录 | 只有歌曲与聆听笔记等数据 | 增加共鸣参数和音乐节点，并接入已确认真实曲目 | 配置缺失导致房间或关联唱片状态不确定 |
| 推荐类型与服务 | 输出三首 `Tonight’s Picks` 和音乐雷达 | 移除常驻三首输出，增加单一、可冻结的关联候选 | 关联唱片与音乐雷达职责重复 |
| 播放控制 | 提供播放时间和基础切歌 | 明确发出拖动与周期重置事件 | 普通进度更新被误判为拖动 |
| 页面 UI | `player-page.tsx` 集中多个大组件 | 只围绕本功能拆分职责，加入房间物件和两步状态 | 页面继续膨胀或焦点顺序退化 |
| 样式与动效 | 固定双栏、唱盘和基础动效 | 增加 3–6 秒共鸣过渡、关联唱片出现/翻面/渐暗 | 动效过强、减少动态模式缺失 |
| 会话状态 | 无最近听过和刚跳过记录 | 新增仅内存的播放历史与周期状态 | 错误跨周期继承或意外持久化 |
| 测试 | 仍断言 `Tonight’s Picks` 和英文标签 | 先替换行为测试，再实施功能 | 旧断言与新设计相互冲突 |
| 文档 | 描述旧页面和旧发现结构 | 同步接口、架构、数据、测试与验收 | 代码和文档再次失配 |

实施顺序不在本规格中定义。只有用户确认本设计和影响分析后，才进入阶段 3 的实施计划。
