## Why

用户在另一台设备或另一浏览器返回 Vibe Listening 时，当前收藏、歌单、场景和续播状态仍只存在原浏览器。P1 需要让这些轻量个人状态随账号恢复，同时继续让用户音乐文件只保留在自己的设备上。

## What Changes

- 接入托管账号登录与退出，并用当前会话而非客户端传入的用户 ID 确定数据归属。
- 新增受行级所有权约束的 PostgreSQL 用户状态存储，同步收藏、歌单、场景、房间/环境声偏好和每设备的播放续播状态。
- 在播放器中显示明确的登录、同步、离线失败和本机未导入提示；未登录或同步失败时仍保留本地播放与本地保存。
- 为本地曲目保存稳定的本机指纹引用；其他设备没有该文件时不得以标题或艺术家猜测替换播放对象。
- 提供账号数据导出申请与账号删除入口；私人记忆、音频 Blob、原始本地路径和住客瞬时状态不上传。
- 不包含云端音乐上传、对象存储、媒体解析 Worker、管理员后台或分享/协作空间。

## Capabilities

### New Capabilities

- `account-authentication`: 让用户以受控会话登录、登出并访问账号级个人数据。
- `account-state-sync`: 将允许同步的播放器状态按账号和设备安全地读取、写入和恢复，并在本地曲目缺失时提供正确降级。
- `account-data-lifecycle`: 让用户请求导出同步状态并删除账号级状态。

### Modified Capabilities

无。

## Impact

- 增加托管 Auth、PostgreSQL、行级访问策略及其环境变量/迁移脚本；初始实现以 Supabase Auth 与 Postgres 为默认托管组合。
- 影响本地 `LocalAppState` 的同步投影、曲目引用模型、P0 repository 组合层、播放器状态提示和相关测试。
- 需要部署环境配置 Supabase URL、匿名公钥与服务端安全密钥；不将密钥、音乐文件或私人记忆提交到仓库。
